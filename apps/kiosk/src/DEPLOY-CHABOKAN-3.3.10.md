# راهنمای دیپلوی امن Bastiyan 3.3.10 روی چابکان

این نسخه عمداً به صورت **Code Update سازگار با پنل‌های نصب‌شده قبلی** طراحی شده است.

## اصل حیاتی
پوشه `data/` در محیط Production باید Persistent باشد و در Deploy جدید پاک یا جایگزین نشود. فایل‌های زیر خصوصاً باید حفظ شوند:

- `data/.client_package_secret` — کلید امضای URL پنل‌های نصب‌شده ویندوز
- `data/clinic_store.json` — تنظیمات مراکز، پزشکان، منشی‌ها، صف‌ها و تنظیمات نمایشگر
- `data/users_store.json`
- `data/sessions_store.json`
- `data/center-logo-*`
- `data/center-qr-*`
- `data/center-media-*`

## چرا پنل‌های نصب‌شده نیاز به نصب مجدد ندارند؟
پنل Windows Native نصب‌شده، رابط اصلی را از همان آدرس سرور بارگذاری می‌کند. در 3.3.10:

1. ساختار `client.php?center=...&role=...&sig=...` تغییر ناسازگار نکرده است.
2. الگوریتم امضای بسته تغییر نکرده است.
3. فایل `.client_package_secret` در Release/Deploy جدید جایگزین نمی‌شود.
4. پس از Deploy، پنل نصب‌شده در اجرای بعدی خودکار کد جدید سرور را دریافت می‌کند.

در نتیجه تا زمانی که **آدرس اصلی سامانه و پوشه data همان قبلی باشند**، نصب مجدد لازم نیست.

## روش پیشنهادی Deploy
1. از داخل سامانه یک Backup کامل بگیرید.
2. مطمئن شوید Storage مربوط به `/var/www/html/data` در چابکان Persistent است.
3. این Release را Deploy کنید؛ `.dockerignore` مانع ورود داده‌های زنده و Secret به Image جدید می‌شود.
4. بعد از بالا آمدن سرویس، ابتدا ورود سوپرادمین و سپس یک پنل نصب‌شده پزشک یا منشی موجود را تست کنید.
5. تست «فراخوان بیمار بعد»، «پایان ویزیت»، تنظیمات نمایشگر و یک فراخوان در TV را انجام دهید.

## ممنوع
- پوشه `data/` Production را با پوشه data داخل یک ZIP قدیمی Overwrite نکنید.
- فایل `data/.client_package_secret` را حذف/بازسازی نکنید؛ در غیر این صورت پنل‌های نصب‌شده قبلی امضای نامعتبر خواهند داشت.
- دامنه اصلی پنل را بدون برنامه مهاجرت تغییر ندهید؛ آدرس برنامه داخل Client نصب‌شده به سرور فعلی اشاره می‌کند.
