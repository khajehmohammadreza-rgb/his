# Bastiyan Windows Native 3.3.20

- فایل `Bastiyan-Windows-Installer-x64.exe` لانچر بومی x64 برای Windows 10/11 است که با Go کامپایل شده و در بسته‌های نصب نقش‌محور صادرشده توسط `/download.php` قرار می‌گیرد.
- فایل‌های `client.json` اختصاصی نقش و مرکز را **حتماً فقط از داخل سامانه و بخش دانلود بسته نصب** بگیرید؛ این مخزن حاوی مشخصات محرمانه مرکز/کاربران نیست.
- نیاز به نصب Node.js، Python، Java، PHP، PowerShell Script یا .NET اضافه ندارد؛ اما برای **نمایش رابط وب** لازم است Edge یا Chrome یا Firefox روی کامپیوتر باشد. بدون هیچ مرورگری، رابط اجرا نمی‌شود. نصاب، مرورگر جدید نصب نمی‌کند.
- راه‌انداز ابتدا Edge، سپس Chrome، سپس Firefox را در مسیرهای معمول Program Files و LocalAppData بررسی می‌کند؛ در Firefox ممکن است صفحه دیالوگ چاپ باز شود.
- چاپ بی‌دیالوگ فقط برای منشی در Chrome/Edge با پرچم `--kiosk-printing` تلاش می‌شود. چاپگر حرارتی باید چاپگر پیش‌فرض ویندوز، سالم و روی اندازه کاغذ مناسب تنظیم شده باشد؛ آزمایش فیزیکی ضروری است.
- مسیر نصب کلاینت در `%LOCALAPPDATA%\Programs\Bastiyan\<PackageKey>` و پروفایل مرورگر در `%LOCALAPPDATA%\Bastiyan\Profiles\<PackageKey>` است. نصب مجدد عمداً پروفایل را پاک نمی‌کند.
- این نسخه با هر بار اجرای میانبر و اتصال HTTPS، `windows-runtime/version.json` را بررسی می‌کند و فقط در صورت یافتن نسخه جدید و تطابق SHA-256، فایل اجرایی جدید را نصب می‌کند. برنامه قبلی تا زمان موفقیت جایگزینی با پسوند `.bak` باقی می‌ماند. کد سمت سرور و رابط وب با بارگذاری مجدد از سرور جدید دریافت می‌شود.
- **استثنا:** کلاینت‌هایی که **قبل از 3.3.12** نصب شده‌اند خودشان سازوکار تعویض EXE را ندارند؛ برای قابلیت‌های جدید راه‌انداز (شناسایی Chrome/Firefox و آپدیت بومی)، باید یک بار نسخه نصب 3.3.12 را روی همان نقش و مرکز اجرا کنید. کاربر و اطلاعات مرکز سمت سرور نباید حذف شود.
- فایل EXE امضای تجاری Authenticode ندارد؛ ممکن است Windows SmartScreen، آنتی‌ویروس سازمانی یا Group Policy برای اجرای آن تأیید مدیر سیستم بخواهد. «نصب بدون هیچ دخالت» در همه سیستم‌ها تضمین‌شدنی نیست.
- فایل `version.json` و EXE نباید به صورت جداگانه یا نامنطبق به سرور منتقل شوند. با HTTPS و پس از Backup، هر دو را با هم منتشر کنید.

## Doctor Quick Assistant (3.3.20)

- در نسخه نصب‌شده **پزشک**، برنامه کمکیِ ویندوزی با همان فایل اجرایی و گزینه `--assistant` آغاز می‌شود.
- کلیدهای سراسری `F8` و `Ctrl+F8` هر دو فقط پنل کوچک را باز/مخفی می‌کنند؛ هیچ‌یک مستقیم بیمار را فراخوان نمی‌کنند.
- پنل کوچک در مرورگر Edge/Chrome با پروفایل همان نسخه پزشک و نشست ورود موجود اجرا می‌شود؛ داده/توکن در آرگومان خط فرمان و URL قرار نمی‌گیرد.
- دستورات فراخوان، تکرار فراخوان و پایان ویزیت از API اصلی `/api` با اعتبارسنجی نقش و شناسه پزشک استفاده می‌کنند.
- برای جلوگیری از فراخوان تکراری، در بازه انجام درخواست، دکمه‌ها غیرفعال می‌شوند. درخواست POST ناموفق خودکار تکرار نمی‌شود.
- در صورت اشغال بودن میانبر توسط نرم‌افزار دیگر، میانبر آزاد فعال می‌شود و ویندوز پیام مناسب می‌دهد.
- این نسخه نیازمند **یک بار به‌روزرسانی Runtime ویندوز** است؛ انتشار کد وب به‌تنهایی کلید سراسری را فعال نمی‌کند. بعد از آن، به‌روزرسان موجود در نسخه >=3.3.12 می‌تواند فایل اجرایی جدید را با SHA-256 دریافت کند.
- آزمون‌های کامپایل و کد انجام شده‌اند؛ رفتار واقعی کلیدهای سراسری و Always-on-top باید روی Windows 10/11 با Edge/Chrome، سامانه بیمه و چند مانیتور نیز آزمایش شود.
