# دیپلوی امن Bastiyan 3.3.11 روی چابکان

این نسخه **Code-only و سازگار با پنل‌های نصب‌شده ویندوز** است.

## قبل از Deploy
1. از داخل سامانه Backup کامل بگیرید.
2. مطمئن شوید `/var/www/html/data` روی Storage پایدار/Persistent قرار دارد.
3. به هیچ عنوان فایل‌های Production زیر را پاک یا Overwrite نکنید:
   - `data/.client_package_secret`
   - `data/clinic_store.json`
   - `data/users_store.json`
   - `data/sessions_store.json`
   - `data/center-logo-*`
   - `data/center-qr-*`
   - `data/center-media-*`
   - `data/backups/`

## چرا پنل‌های نصب‌شده نیاز به نصب مجدد ندارند؟
پنل Windows Native فقط لانچر محلی است و رابط و منطق جاری را از همان سرور Bastiyan دریافت می‌کند. در نسخه 3.3.11:
- Base URL کلاینت تغییر نکرده است.
- امضای `client.php` تغییر ناسازگار نکرده است.
- کلید `data/.client_package_secret` بخشی از Release نیست و باید روی Storage قبلی باقی بماند.
- `index.html` فایل‌های UI را با cache-buster نسخه `3.3.11` می‌خواند؛ بنابراین پنل نصب‌شده با اجرای بعدی UI جدید را دریافت می‌کند.

## تست بلافاصله بعد از Deploy
1. ورود سوپرادمین و ورود به `/doctor`.
2. انتخاب یک پزشک و مشاهده فقط یک پنل فراخوان یکپارچه.
3. سناریوی ۵ نوبت:
   - فراخوان ۱
   - بدون پایان ویزیت → فراخوان نفر بعد → ۲
   - پایان ویزیت ۲
   - فراخوان نفر بعد → باید دوباره ۱ فراخوان شود، نه ۳
4. تکرار فراخوان و بررسی افزایش `callCount` و ساعت فراخوان.
5. پایان پذیرش جدید برای پزشک و بررسی پیام TV.
6. اطمینان از ادامه فراخوان نوبت‌های قبلی پس از پایان پذیرش جدید.

## ممنوع
- Deploy یا Extract دستی یک ZIP قدیمی روی پوشه `data`.
- حذف `.client_package_secret`.
- تغییر دامنه یا Base URL بدون برنامه مهاجرت کلاینت‌ها.
