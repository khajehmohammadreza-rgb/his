# گزارش بررسی و اصلاح Bastiyan Kiosk 3.3.5

## دامنه بررسی
- ساختار کامل بسته و فایل‌های PHP/JS/HTML/JSON/CSS/صوت
- مسیرهای احراز هویت و نشست نقش‌های پزشک، منشی، نمایشگر و سوپرادمین
- تولید بسته‌های نصب ویندوز و قفل مرکز/نقش
- نمایشگر TV، صف، فراخوان، QR، تیکر، مدیای نمایشگر و تنظیمات مرکز
- اعتبارسنجی داده‌های تنظیمات و سازگاری API

## اصلاحات این نسخه
1. ادغام پایدار تنظیمات تیکر: مدیر اصلی تیکر در «تنظیمات نمایشگر مرکز» باقی می‌ماند و رابط قدیمی پس از هر رندر مجدد نیز مخفی می‌شود.
2. API تیکر ورودی را نرمال و محدود می‌کند: شناسه تکراری/نامعتبر اصلاح می‌شود، متن خالی حذف می‌شود و طول متن و تعداد پیام‌ها محدود است.
3. شماره‌های مراجعه‌کننده در TV با Fit خودکار و فونت تطبیقی نمایش داده می‌شوند تا اعداد چندرقمی بریده نشوند.
4. برای QR فضای امن رزرو شده است تا روی تیکر، کپی‌رایت، دکمه‌های کنترل یا سایر اجزای ثابت قرار نگیرد.
5. نسخه پزشک/منشی بدون نام کاربری انگلیسی کار می‌کند: فهرست فارسی کاربران فعال همان مرکز نمایش داده می‌شود و ورود با شناسه واقعی حساب + رمز انجام می‌شود.
6. آخرین پزشک/منشی انتخاب‌شده برای همان مرکز/نقش ذخیره می‌شود. رمز عمداً در LocalStorage یا فایل تنظیمات به صورت متن ساده ذخیره نمی‌شود و Password Manager مرورگر/ویندوز می‌تواند آن را مدیریت کند.
7. نسخه برنامه و بسته‌های نصب به 3.3.5 ارتقا یافت و Cache Busting نیز به‌روزرسانی شد.

## تست‌های انجام‌شده
- PHP lint: api.php, client.php, download.php, setup.php, guard.php — بدون خطای Syntax.
- JavaScript syntax check: enhancement module و اسکریپت TV — بدون خطای Syntax.
- اعتبارسنجی JSON: manifest/chabok/data/bootstrap — همه قابل Parse.
- اعتبارسنجی صوت: همه فایل‌های MP3 موجود واقعاً codec=mp3 دارند.
- تست Runtime صفحه نصب‌شده: Doctor و Secretary با امضای واقعی مرکز باز شدند و Select فارسی کاربران فعال تولید شد.
- تست تولید بسته نصب Doctor: HTTP 200، ZIP سالم و unzip -t بدون خطا؛ client.json نقش/مرکز/نسخه را درست ثبت کرد.
- داده‌های clinic_store و sessions_store پس از تست به نسخه اولیه بازگردانده شدند.

## محدودیت تست
محیط بررسی Linux است؛ بنابراین اجرای واقعی GUI نصب PowerShell/VBS روی یک ویندوز فیزیکی در این محیط ممکن نبود. خود Generator، ساخت ZIP، محتوای Installer، مسیرهای Launch و فایل‌های خروجی به‌صورت استاتیک و Runtime سمت سرور بررسی شدند. برای تأیید نهایی نصب GUI فقط یک Smoke Test روی Windows 10/11 واقعی پس از Deploy توصیه می‌شود.
