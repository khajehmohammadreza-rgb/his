# Bastiyan HIS 5.1.1 — R21 Deep Refactor

## تغییرات اصلی
- داشبورد از نو طراحی شد و شاخص‌های زنده پذیرش، صف، مالی، موجودی و اقدامات سریع را نمایش می‌دهد.
- بکاپ خودکار مرکز اکنون توسط مدیر قابل برنامه‌ریزی است: روشن/خاموش، هر N ساعت یا ساعت‌های مشخص روزانه، و تعداد نسخه قابل نگهداری.
- باگ بیمه در فرم ثبت بیمارِ جریان پذیرش برطرف شد؛ کاتالوگ بیمه و قراردادهای فعال به فرم پاس داده می‌شود.
- تنظیمات سرویس‌ها در یک مسیر «یکپارچه‌سازی و API» متمرکز شد. مسیر ویرایش تکراری API از صفحه نصب/آپدیت حذف شد.
- خزانه رمزگذاری‌شده برای کلیدهای Chabokan AI / Platform و Credential بیمه‌ها اضافه شد؛ Secret کامل در پاسخ مرورگر بازگردانده نمی‌شود.
- لیلیان ابتدا از API سازگار OpenAI چابکان استفاده می‌کند و در نبود تنظیمات آن به Gemini/منطق محلی قبلی برمی‌گردد.
- ابزار Super Admin برای فیلتر و استخراج اطلاعات تماس بیماران (از جمله بیماران خانم) اضافه شد.
- حالت «توسعه» فقط برای Super Admin در رابط لیلیان اضافه شد. عملیات حساس همچنان تابع مجوز سرور، Snapshot و مسیر امن آپدیت/Rollback است.
- ثبت سریع خدمت/کالا در انتخابگر بالینی اضافه شد و مورد جدید بلافاصله در کاتالوگ اصلی سامانه ثبت می‌شود.
- منشی/ادمین می‌تواند ورود و خروج سایر کارکنان را از داشبورد ثبت کند و هویت ثبت‌کننده نگهداری می‌شود.
- سال مالی فعال در State مرکزی استاندارد شد و رکوردهای مالی قدیمی فاقد fiscalYear بدون حذف داده برچسب‌گذاری می‌شوند.
- رندر تکراری مدیریت پیامک حذف شد.

## اتصال بیمه بدون API
Credential پزشک به‌تنهایی یک API پایدار ایجاد نمی‌کند. معماری R21 دو حالت دارد: `official_api` برای وب‌سرویس رسمی پس از اخذ دسترسی، و `portal_rpa` برای پل مرورگر/RPA کنترل‌شده در محیط مورد اعتماد. از مهندسی معکوس Login/CAPTCHA یا ذخیره Credential در مرورگر اجتناب شده است.

## ایمنی توسعه و استقرار
سیستم آپدیت موجود همچنان Snapshot/Backup، تست سلامت، Commit و Rollback دارد. کلید پلتفرم و Deploy Hook چابکان اکنون محل امن تنظیم دارند؛ اجرای خودکار Deploy فقط وقتی Endpoint/Hook معتبر خود سرویس تنظیم شده باشد مجاز است.
