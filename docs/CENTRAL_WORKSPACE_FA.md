# فضای مرکزی توسعه باستیان

**هدف:** همه سورس‌ها، فایل‌های لازم برای ساخت، راهنماها و فرایندهای انتشار در یک مخزن GitHub باشند تا از هر رایانه با یک حساب GitHub بتوان ادامه داد؛ هر محصول داخل پوشه خودش باقی بماند.

> وضعیت امنیتی: تغییر Visibility به Private هنوز باید در تنظیمات خود GitHub انجام شود. ثبت این سند به معنی خصوصی‌شدن مخزن نیست.

## ساختار مرجع

| مسیر | محصول | وضعیت فعلی |
| --- | --- | --- |
| `apps/his/src/` | Bastiyan HIS | سورس موجود روی GitHub فعلاً **R25 / 5.1.4** است؛ نسخه جدیدتر **R37 / 5.1.16** فقط به‌صورت بسته آماده انتشار خارج از مخزن وجود دارد. |
| `apps/kiosk/src/` | Bastiyan Kiosk | منابع متنی 3.3.20 موجودند؛ کد جدیدتر و دارایی‌های اجرایی کامل هنوز همگام نیستند. مخزن `kiosk` تا انتقال کامل حفظ شود. |
| `apps/catalog/src/` | Bastiyan Catalog | منابع و ابزارهای ساخت موجود، اما سازگاری نسخه‌های انتشار نیازمند اعتبارسنجی است. |

## چرا کد و داده از هم جدا هستند؟

**داخل Git:** تمام کد PHP/JS، فایل‌های ایستا و تصاویر عمومی مجاز، اسکریپت‌های ساخت، راهنماها و آزمون‌ها. فایل‌های دودویی دارای حق نشر صرفاً در صورت داشتن مجوز نگهداری شوند.

**بیرون Git:** دیتابیس SQLite واقعی، اطلاعات بیماران، شماره تماس/سوابق، لاگ حساس، بکاپ واقعی، `config.local.php`، توکن و رمز. در چابکان مسیرهایی مثل `/app/api/data` و `/app/uploads` باید مستقل از هر Deploy دائمی باشند و قبل از هر انتشار از آن‌ها بکاپ معتبر تهیه شود.

**چرا حتی در مخزن خصوصی؟** Private بودن جایگزین کنترل دسترسی دیتابیس، رمزگذاری پشتیبان، نگهداری اسرار و محافظت از سابقه Git نیست. یک اشتباه یا نشت حساب نباید اطلاعات بیماران را همراه سورس آشکار کند.

## پس از خصوصی‌سازی

1. در GitHub: Repository → Settings → General → Danger Zone → Change repository visibility → Private. این تغییر از طریق اتصال فعلی ChatGPT قابل فراخوانی نیست.
2. با همان حساب روی همه دستگاه‌ها وارد GitHub شو؛ برای استفاده از Git روی رایانه‌های مختلف SSH Key یا Credential Manager فعال کن.
3. بعد از تغییر دسترسی، GitHub App متصل به ChatGPT و مجوزهای Actions را بازبینی کن. خصوصی‌کردن ممکن است GitHub Pages عمومی را قطع کند؛ اما خود سایت HIS مستقر روی چابکان به شرط مستقل‌بودن استقرار، خاموش نمی‌شود.
4. تا انتشار کامل R37 و تأیید فضای دائمی چابکان، نسخه موجود `main` را برای Deploy جدید مرجع قرار نده.

## قاعده هر انتشار

`توسعه روی شاخه → آزمون → بازبینی اطلاعات حساس → Merge → بکاپ معتبر و تست بازیابی → Deploy روی چابکان → کنترل سلامت و قابلیت برگشت`

مخزن مستقل `kiosk` تا همگام‌سازی کامل و تأیید عملکرد ابزار ساخت حذف یا جابه‌جا نشود.

## انتقال R37 بدون نیاز به نصب Git روی رایانه

**آماده شده، اما هنوز اجرا نشده است**؛ مخزن اکنون عمومی است. پس از Private کردن مخزن، فایل آمادهٔ `Bastiyan-HIS-R37-GITHUB-SOURCE-CODE-ONLY.zip` را بدون استخراج به مسیر `incoming/his/Bastiyan-HIS-R37-GITHUB-SOURCE-CODE-ONLY.zip` در GitHub آپلود کنید.

Workflow با نام `Bastiyan HIS R37 — Import verified source archive` به‌صورت خودکار اجرا می‌شود؛ بسته را با SHA256 ثابت `79cc6df9b81c25daad9a75211d9e1b230df2991688b744e99648f382339fcb78` اعتبارسنجی کرده و سورس `apps/his/src/` را **در شاخه جداگانه** با نسخه 5.1.16 آماده Pull Request می‌کند. فایل‌های تست قدیمی R25 در `apps/his/tests-legacy-r25/` حفظ می‌شوند. بخش‌های دیگر مخزن دست‌نخورده می‌مانند.

**این مرحله به‌هیچ‌وجه Deploy روی چابکان نیست**؛ پیش از استقرار عملیاتی، تطبیق مسیر داده دائمی و بکاپ تأییدشده الزامی است. علاوه بر آن، بسته سورس عمومی فاقد فونت‌های دارای مجوز و فایل‌های حساس است؛ برای استقرار کامل باید منابع مجاز جداگانه تأمین شوند.
