# هماهنگ‌سازی انتشارهای باستیان با مخزن مرکزی

این تغییر روی شاخه آزمایشی انجام می‌شود، بدون استقرار خودکار روی سرور عملیاتی.

| محصول | نسخه قابل تأیید | وضعیت فایل منبع |
|---|---|---|
| Bastiyan HIS | 5.1.4 R24 validated | در حال انتقال در apps/his/src |
| Bastiyan Catalog | 2.2 | از قبل در apps/catalog/src و CI |
| Bastiyan Kiosk | 3.3.19 | فایل منبع در محیط فعلی موجود نیست؛ انتقال انجام نشده |
| HIS R25 Chabokan AI trial | 5.1.4 R25 آزمایشی | فایل قابل بازیابی نیست؛ مبنای عملیاتی فرض نشده |

فایل R24 پس از حذف باینری قلم‌های اختصاصی و جایگزینی نمونه پیکربندی اشتباه MySQL با قالب SQLite، به‌عنوان «سورس» وارد می‌شود. خروجی ZIP نصب/آپدیت نهایی و آماده Production نیست؛ صحت update-manifest/checksum قدیمی پس از تغییر محتوا تضمین نمی‌شود.

## اصول استقرار
- مسیرهای فعلی ریشه GitHub برای HIS قدیمی دست‌نخورده باقی می‌مانند.
- تا زمان تست کامل استقرار، به هیچ سرور Chabokan/NetAfraz فرمان deploy ارسال نمی‌شود.
- هیچ API Key، رمز عبور، پرونده بیمار، دیتابیس و فایل Backup داخل مخزن عمومی نگهداری نمی‌شود.
- انواع کلیدها مستقل: Chabokan AI، Chabokan Platform، Gemini، Kavenegar.
- اتصال بیمه در HIS نیازمند مجوز و شرایط سامانه بیمه است؛ هیچ مسیر عبور از OTP/CAPTCHA فعال نشده است.
- فونت‌های B Titr و B Nazanin باید در محیط مورد استفاده از منبع دارای مجوز فراهم باشند.
- برای آخرین کیوسک و R25 آزمایشی ابتدا باید بسته واقعی فراهم و با SHA تأیید شود.
