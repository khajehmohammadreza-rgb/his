# حداقل الزامات امنیت و نگهداری مخزن

- هر Pull Request باید تست‌های «Repository hygiene» و تست سورس مرتبط را با موفقیت بگذراند.
- بررسی نام فایل‌ها **جایگزین اسکن محتوایی اسرار یا بازبینی کد نیست**؛ مسیرهای حساس قبلی در تاریخچه Git نیز ممکن است باقی مانده باشند.
- وضعیت مخزن، دسترسی‌ها و محدودسازی شاخه main از Settings → Rules / Branch protection مدیریت شود. در صورت پشتیبانی طرح حساب، ادغام فقط پس از موفقیت CI و بازبینی انسانی انجام شود.
- فعال‌سازی هشدارهای امنیتی و اسکن وابستگی‌ها/Secrets در GitHub Settings توصیه می‌شود.
- کلیدها باید فقط در محیط اجرای نرم‌افزار یا GitHub Actions Secrets (در صورت نیاز واقعی به ساخت) نگهداری شوند.
- **هیچ Deploy خودکار به مرکز درمانی** در این مرحله فعال نشده است.

## گزارش یافته‌های امنیتی — ۱۴ اکتبر ۲۰۲۶

دو فایل اولیه‌سازی قدیمی Kiosk از سورس **عمومی** HIS حذف شدند؛ حاوی هش حساب‌های کاربری مدیر/پزشک/منشی و نمایشگر بودند. هش را نباید معادل رمز امن در نظر گرفت؛ به‌خصوص اگر رمز انتخابی ضعیف یا در سامانه دیگری تکرار شده باشد.

1. در محیط عملیاتی، رمزهای حساب‌های مرتبط (مدیر، پزشکان، منشی، نمایشگر و حساب‌های مشترک) تعویض شوند؛ تا پیش از تغییر، آنها در معرض خطر فرض شوند.
2. نشست‌ها/توکن‌های قبلی در صورت پشتیبانی باطل شوند و رخدادهای ورود نامعمول بررسی شوند.
3. پروفایل‌ها و فایل‌های اولیه‌سازی واقعی فقط روی فضای خصوصی پایدار نگهداری شوند. برای نصب تازه از فرایند نصب و تعریف رمز جدید استفاده شود، نه هش پیش‌فرضِ نسخه‌بندی‌شده.
4. پاک‌سازی تاریخچه Git نیازمند تصمیم و هماهنگی درباره Cloneها و خروجی‌های قدیمی است. **حذف از شاخه جاری تاریخچه عمومی را پاک نمی‌کند.**
5. درباره تغییرات روی چابکان هیچ عملی انجام نشده؛ این موارد باید در محیط واقعی بررسی شوند.

## موارد خاص
- **HIS عمومی:** در ممیزی قبلی سابقه SESSION_SECRET در تاریخچه ثبت شده؛ کلیدهای نشست فعال باید در محیط سرور تعویض شوند، نشست‌های قدیمی بررسی شوند و پیش از عمومی/خصوصی کردن یا بازنویسی تاریخچه از مسئول استقرار تأیید گرفته شود.
- **Kiosk خصوصی:** مخزن خصوصی هم محل نگهداری داده بیمار و کلید جفت‌سازی نیست؛ سورس GUI کامل هنوز به مخزن منتقل نشده است.
