# Bastiyan HIS | مدیریت هوشمند مراکز درمانی

**بخشی از خانواده نرم‌افزارهای باستیان** — مدیریت پذیرش، پرونده بیمار، صندوق، ترخیص، قراردادهای بیمه، انبار و عملیات مرکز درمانی؛ با رابط فارسی و معماری قابل توسعه.

> **وضعیت مهم:** این مخزن در حال حاضر *منبع معتبر تأییدشده برای استقرار آخرین نسخه عملیاتی* نیست. فایل‌های قدیمی ریشه و بسته‌های متفاوت در کنار سورس جدیدتر نگهداری می‌شوند. هیچ به‌روزرسانی روی مرکز واقعی صرفاً با دریافت شاخه `main` انجام نشود.

## نمای پروژه

| بخش | جایگاه | وضعیت قابل اتکا در GitHub |
| --- | --- | --- |
| **Bastiyan HIS** | سامانه اصلی مدیریت درمانگاه و بیمارستان | `apps/his/src/`؛ فایل نسخه `5.1.4 / R25`؛ نیازمند تطبیق با آخرین بسته توسعه و آزمون استقرار |
| **Bastiyan Catalog** | ابزار جانبی گردآوری کالا و بارکد | `apps/catalog/src/`؛ سورس و جریان ساخت آزمایشی موجود است |

**محصول سوم در نقشه راه:** **ClinicSite**، سایت اختصاصی کلینیک با رزرو، پیامک، حساب بیمار و پرداخت اینترنتی؛ مخزن مستقل آن هنوز ایجاد نشده است.

## مسیرهای اصلی

- `apps/his/src/` — سورس PHP و JavaScript سامانه HIS؛ نه تضمین نسخه منتشرشده
- `apps/catalog/src/` — سورس Catalog و ابزارهای ساخت
- `apps/kiosk/src/` — نسخه نگهداری‌شده منابع متنی Kiosk برای مهاجرت؛ مرجع رسمی توسعه جدید نیست
- `archive/his/` — آرشیو تاریخی؛ **منبع استقرار نیست**
- `.github/workflows/` — بررسی سورس و ساخت آزمایشی؛ فاقد مجوز ضمنی استقرار روی Production
- `docs/` — راهنمای توسعه، امنیت، هماهنگی نسخه‌ها و انتشار

## اصول توسعه

1. هر تغییر روی شاخه مستقل و از طریق Pull Request انجام می‌شود؛ کد پایدار بدون بررسی جایگزین نمی‌شود.
2. نسخه مرجع با **سورس + شماره نسخه + commit + گزارش آزمون** ثبت می‌شود. نام ZIP به‌تنهایی معیار آمادگی انتشار نیست.
3. استقرار فقط پس از پشتیبان قابل‌بازیابی، بررسی تغییرات پایگاه داده و آزمون پذیرش در محیط آزمایشی انجام می‌شود.
4. کلیدها، اطلاعات بیماران، بکاپ و فایل‌های تنظیمات مرکز هرگز در Git ذخیره نمی‌شوند.
5. کدهای قدیمی ریشه تا شناسایی وابستگی استقرار فعلی جابه‌جا یا حذف نمی‌شوند.
